# PennyAgent：基于 Strix 的 PoC 功能与交互设计

日期：2026-11-06。状态：依据用户逐项确认的需求整理，尚未开始功能实现。
依据：`docs/PROGRESS-strix-mvp.md` 中的最新决定；较早讨论与本文冲突时，以最新确认内容为准。

## 1. 本期目标

在现有 PennyAgent 前端中接入真实 Strix 执行能力，完成登录、创建测试、查看过程、人工插话、运行控制、查看发现和保存产物的完整流程。

开发及执行环境为本机，同一时间运行一个测试任务，保留该任务内部的多 Agent 协作。使用一套模型 API 配置。本期前端只配置开源版 Strix 原生支持的黑盒 Web App Pentest，不加入 White-box、Git Repository、Local Codebase、SAST 或源码修复流程。

## 2. 页面职责

| 页面 | 本期职责 |
|---|---|
| Home | 保留当前展示项，接入真实任务及结果；增加聊天输入框 |
| Pentests | 原 Tasks，更名；测试列表、创建向导、执行详情、发现和产物 |
| 现有风险 | 原 Workspace，仅更名，现有内容保持不变 |
| Agents | 实际 Agent、父子关系、状态、消息及运行控制 |
| Workflows | 保存及使用可复用测试配置 |
| Skills | Strix 现有技能目录、详情、来源版本及使用情况 |
| Tools | Strix 现有工具目录、详情、可用情况及调用记录 |
| Models | 接口地址、API Key、模型名称和连接测试 |
| 协同通道 | 保留导航入口，内容暂时留空 |

移除 Sessions 的独立侧栏入口，保留会话数据和聊天能力。维持现有视觉风格、组件规范及用户指定的中英文名称。现有风险页面不改造为产物中心，测试产物在 Pentests 详情查看。

## 3. Home 与 AI Copilot

### 3.1 入口及形态

- Home 输入框参考用户提供截图的对话输入布局，沿用现有视觉风格。
- 从 Home 发送消息后进入全屏聊天，首条消息只发送一次。
- 其他页面调用 AI Copilot 默认打开侧边栏。
- 提供全屏与侧边栏切换按钮；全屏占据主内容区域，保留左侧导航。
- 形态切换共用当前会话、消息、附件和任务关联，不重复创建会话或测试。
- 从全屏切回侧边栏时恢复原页面及其界面状态。
- 聊天交互打开时，右上角原 AI Copilot 按钮改为“开始渗透测试”，跳转 Pentests；该按钮不直接启动任务。
- 保留明确的缩小、展开及关闭操作；关闭聊天展示不终止测试。

### 3.2 聊天创建测试

普通问答保留在会话中。识别到测试需求后整理任务草稿，缺少输入时请求补充；展示可检查的配置卡片，用户明确确认后启动真实任务。

配置卡片与 Pentests 创建向导共用任务数据和校验规则。发送问候、切换视图或浏览历史均不自动启动测试。

### 3.3 运行中的消息

默认接收对象为主 Agent，允许在 Agents 详情中选择子 Agent。展示消息接收对象、发送时间和处理状态。消息进入执行端邮箱与 Agent 实际响应分别记录。

普通聊天需要产品层连接同一模型配置；Strix 测试执行接口与普通聊天接口的适配分别实现，不假定每条对话都需要创建 Strix 测试任务。

## 4. 黑盒 Web App Pentest 输入

本期前端只提供开源版 Strix 原生黑盒测试配置。创建页面保留 Target、Authentication / Instructions、Scan Mode、Resource Budget 四个配置模块，以及独立的 Review & Launch 确认步骤。

### 4.1 Target

支持以下目标类型：

- Web Application：完整 HTTP/HTTPS URL、域名、子域名和指定路径。
- IP Address：合法 IPv4 或 IPv6；带协议和端口的服务使用 URL。
- API Specification：OpenAPI/Swagger JSON、OpenAPI/Swagger YAML、Postman Collection JSON 和 `postman://` 在线 Collection。

目标可以添加多个。目标列表文件按每行一个目标读取，忽略空行及 `#` 开头的注释。仅输入域名时按 Strix 原生规则补充 HTTPS。CIDR 网段不作为本期原生目标类型。

API Specification 用于提取 Base URL、接口、参数、请求体和认证要求。规范缺少 Base URL 时，用户还需要提供实际 API 地址。在线 Postman Collection 需要配置 `POSTMAN_API_KEY`，环境通过 `?env=<environment-uuid>` 指定。

### 4.2 Authentication / Instructions

Strix 没有独立认证模式和结构化 Credential Profile。前端提供可选的 Custom Instructions 多行输入框，用户在其中填写账号、密码、多个角色、API Key、请求头、认证流程、关注点及排除路径。

复杂说明可以通过 Instruction File 提供。`--instruction` 与 `--instruction-file` 二选一。密码和密钥在 Review & Launch 中只显示“已配置”，不直接显示内容。

### 4.3 Scan Mode

前端提供 Strix 原生的三个选项：Quick、Standard、Deep，默认值为 Deep。页面不增加自定义扫描深度、扫描时长、Agent 数量、并发数量、请求速率或端口扫描参数。

### 4.4 Resource Budget

前端提供：

- Maximum LLM Budget (USD)：可选，填写时必须大于零。
- Maximum Turns per Agent：默认 500，必须是大于零的整数。

预算达到上限后由 Strix 原生执行逻辑结束任务。页面不增加最大扫描时长、最大 Agent 数量、最大并发数量、最大请求数量或自定义请求速率。

本地目标仍需按照执行容器的实际网络环境进行可达性验证。

## 5. Pentests 创建与详情

### 5.1 创建流程

1. 进入 New Web App Pentest。
2. 在 Target 中选择目标类型，填写一个或多个目标，或上传目标列表/API 规范。
3. 在 Authentication / Instructions 中填写 Custom Instructions，按需上传 Instruction File。
4. 选择 Scan Mode。
5. 设置 Resource Budget。
6. 在 Review & Launch 中查看 Target List、Target Types、指令配置状态、扫描模式和资源限制，明确确认后启动。

任务快照保存目标来源、目标列表、指令来源、扫描模式、预算、回合上限、模型名称和有效配置。密码、API Key 及其他敏感字段单独保存，摘要与报告只保留适当引用。

### 5.2 测试详情

包括概览、执行过程、Agent 活动、漏洞发现和产物，展示启动时间、当前状态及原生可获取的用量。具体标签排布沿用组件规范，在页面实现时确定。

发现展示严重程度、描述、影响对象、复现说明及原生证据等实际字段。没有取得证据的字段明确显示缺失情况；不把模型生成的结论自动升级为平台独立复核结论。

保留 Strix 原生报告及文件查看、下载入口。报告格式、额外模板和导出类型稍后讨论。截图中的 Network、Terminal、分享等控件不自动计入本期。

## 6. Agent、技能、工具与配置复用

- Agents 展示本次运行实际生成的主 Agent 与子 Agent。固定角色样例及数量需替换，空任务显示真实空状态。
- Skills 与 Tools 首批使用所选 Strix 版本的现有内容；实际数量由目录、注册及运行信息产生。
- 技能正文、内部策略与用户可选技能分别表达；单次加载数量限制不推导为整个会话的技能累计上限。
- 工具区分原生函数、沙箱程序及已配置 MCP 工具；“目录存在”“环境可用”“曾经调用”分别展示。
- 首期不增加自研测试技能或工具。在线编辑、外部安装和市场能力没有纳入确认范围。
- Strix 的测试方法由系统提示词、扫描模式技能、专项技能与运行中决策共同组织；平台 Workflows 保存可复用配置，不要求固定步骤执行图。
- Workflow 保存测试类型、模式、指令及可复用资料等配置，敏感身份资料在执行时单独提供。模型使用全局配置，不增加多模型分配。

## 7. 运行控制

| 操作 | 用户可见行为与实际限制 |
|---|---|
| 发送消息 | 向主 Agent 或指定子 Agent 发消息，记录受理及响应 |
| 中止 Agent | 对允许状态中的指定 Agent 及其子树发起停止请求 |
| 中止任务 | 对主 Agent 子树发起停止，执行端确认后更新任务状态 |
| 暂停 | 请求预算暂停，通常在下一次模型调用前生效，当前操作可能继续完成 |
| 恢复 | 解除预算暂停；费用耗尽时需要调整费用上限 |
| 恢复执行 | 使用原生保存状态继续中断任务，条件满足时才提供入口 |
| 再次测试 | 复制原配置并经确认创建独立执行记录，原结果保留 |

适配方向：`agent.send_message`、`agent.stop` 对接 TUI 对应行为；预算暂停恢复通过协调器方法接入。预算方法不等于已存在同名 TUI 命令。`event_sink`、`status_sink` 用于接收运行事件及状态，具体签名、线程与异步行为按固定版本核实。

停止入口支持的 Agent 状态按源码核查为 running、waiting、budget_paused。前端显示正在暂停、正在停止等过渡状态，不能在仅提交请求后宣告全部操作已终止。恢复预算涉及费用上限，无自动顺延截止时间的承诺。

## 8. 状态与文件保存

保存任务配置、状态变化、会话与用户消息、Agent 关系及活动、工具事件、发现、原生恢复材料及产物引用。记录工具实际输出，不收集或承诺展示模型隐藏推理。

关闭或刷新网页不终止后台测试，重开页面重新取得当前状态及历史记录。服务重启后保留历史并识别中断，用户决定是否恢复，不自动发起新测试。

数据库记录、Strix 原生恢复材料和运行容器的存续分别检查。原生恢复条件不足时保留记录并说明原因，允许用户选择再次测试；不把持久化任务记录作为任意断点恢复的保证。

Models 中的密钥、Custom Instructions 中的密码和任务敏感资料不进入普通对话、任务公开摘要或下载报告。Instruction File 按独立受保护输入保存，并在执行时传递给 Strix。

## 9. 本期排除与待定项

本期不增加资产责任管理、补丁安装、整改及供应商协作、自动部署、多执行节点及并发调度、商业计费、周期运行、邮件和外部协同渠道集成。

审批工具与审批执行机制暂不实现，实现方式待定；本期不宣称存在逐工具审批约束。Caido iframe、跳转及人工流量工作台入口暂不提供，Strix 所需原生代理依赖按实际需要保留。

待定：报告格式与扩展导出；审批实现；平台登录的具体实现；固定 Strix 版本及适配验证；会话历史的具体选择入口。技术方案在后续设计单元明确，不提前写成完成结果。

## 10. 验收检查

- 登录后可进入 Home、创建真实 Web App Pentest，聊天与表单两种方式共用确认启动流程。
- Copilot 双形态及默认入口符合约定，切换保留消息、附件及原页面状态。
- 导航更名正确，Sessions 独立入口移除；现有风险内容保持不变，协同通道为空。
- 接入真实 Agent、工具事件、发现及产物；数量不使用生成样例代替。
- 本机同一时间一个测试任务；实际暂停、中止及恢复状态与执行端一致。
- 刷新、关闭网页及服务重启后的状态保留分别验证；恢复与再次测试形成清楚记录。
- 黑盒目标、目标列表、API 规范、Custom Instructions、Instruction File、扫描模式和资源预算均按原生参数验证；敏感资料不出现在普通日志及报告。
- 原生报告与产物可以查看，额外报告格式不作为本轮验收条件。
