# Issue #10：原生 Skills 与 Tools 目录

## 来源与边界

- 目录沿用任务启动的 Strix 源码选择顺序：显式环境变量、可读取的安装记录、仓库附带版本。
- 附带版本读取 `STRIX_COMMIT`；独立 Git 源码读取该目录的实际 HEAD。版本来自该目录的 `pyproject.toml`。
- 技能正文来自 `strix/skills`；`scan_modes`、`coordination`、`analysis` 为该固定版本的内部策略，其余为用户可选技能。
- 原生函数通过 Python 标准库 AST 读取 `_BASE_TOOLS`、生命周期函数和可选交互函数的定义与文档。工具目录包含条件装配的函数；目录存在不代表当前任务已经装配或调用。
- SDK 沙箱能力来自工厂装配代码；沙箱程序条目来自 `tooling` 使用说明，仅说明文档中存在对应条目。
- MCP 读取原生位置 `STRIX_MCP_CONFIG` 或 `~/.strix/mcp-servers.json`，应用 `STRIX_MCP_ONLY` / `STRIX_MCP_EXCLUDE` 选择。显示连接名称与声明的 `allowed_tools`，并从所选任务已保存的 `search_mcp_tools`／`get_mcp_tool_schema` 结构化输出补充工具名称和来源事件。不返回 URL、命令、认证、环境变量或远端工具描述，不启动连接或程序。缺少可识别的发现结果时明确说明目录未知。
- 环境可用性保持“尚未核验”；本工单没有执行环境探测。MCP 读取失败有独立状态。
- 不增加技能编辑、安装、市场或扫描操作。界面复用 Fluid Functionalism 的 Button、CardGroup、Card 和字体配置。

## 公开接口

`GET /api/native-catalog`，需要现有平台会话，响应禁止缓存。

支持 `kind=skill|tool`、`category`、`q`、`id`、`taskId`。搜索匹配名称与分类，详情返回原始技能正文或函数文档。

任务调用记录读取该任务 `events.jsonl`，保留任务、Agent、时间、事件位置和调用 ID，不返回调用参数。读取完整事件文件，覆盖第 200 条以后的记录。损坏或未完成的事件行不产生调用记录；文件读取失败独立报告。

- SDK `tool_called` 记录标记为调用事件。
- `response.output_item.done` 记录标记为模型调用请求，执行结果保持未记录。
- 兼容旧适配器保存的 SDK 字符串表示，仅提取完成事件中的函数名称与调用 ID，不执行字符串内容。
- `load_skill` 的结构化参数用于关联技能加载请求。未记录的预载技能与 shell 内部程序使用不推断为已使用。
- 任务保存的 Strix 提交与当前源码不同，调用记录保留原始名称并停止目录映射；任务未保存版本时明确提示名称映射仅供查询参考。

## 页面

Skills 与 Tools 替换既有生成样例，支持真实分类、搜索、详情、正文、来源提交、任务选择、调用记录及来源任务跳转。侧栏计数和 Dashboard 的技能／工具计数读取实际目录，其余 Dashboard 内容保持原有范围。

全局命令菜单保留模块导航，移除生成样例工具搜索结果。聊天页面回归测试使用新目录搜索框，继续验证聊天形态切换后保留筛选状态。

## 测试边界

经用户确认：目录公开 API 与浏览器页面。测试使用独立数据目录和目录测试专用 Next 输出目录；运行事件与 MCP 配置使用文件系统边界的确定内容。未启动真实扫描、未连接 MCP、未安装工具。

验证结果见 `docs/verification/issue-10/verification.json`。测试覆盖与真实环境可用性分别记录。

## 审查修复

- 同一调用的模型请求与 SDK 调用事件合并时，同步事件编号、时间、状态，并继续读取后到的结构化参数，保留技能和 MCP 关联。
- 未声明 `allowed_tools` 的 MCP 连接可以从任务保存的发现结果补充目录。该来源保留任务、Agent、事件位置和调用 ID；仅说明曾获得工具名称，环境可用性保持尚未核验。
- 服务进程的 PATH 可能指向 Python 3.9。目录解析优先使用 Strix 运行环境的解释器；回归测试用不可用的 PATH Python 验证此选择。
- 旧事件若仅有字符串形式且缺少结构化工具输出，工具发现清单保持未知；不从文本推断执行成功。
