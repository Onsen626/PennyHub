# PennyAgent：Strix 进攻型安全 PoC 实施规格

日期：2026-11-06。
状态：功能范围与测试边界已获用户确认；任务跟踪位置为 Onsen626/PennyHub 的 GitHub Issues，发布标签为 ready-for-agent。功能尚未实现。

## Problem Statement

用户已有 PennyAgent 操作界面，但测试、聊天、Agent、工具和结果主要由示例数据驱动，尚未形成通过页面使用 Strix 的真实操作流程。

本期需要在本机开发环境中接入 Strix 现有进攻型安全能力，使用户能够通过表单和对话创建测试、查看真实过程、参与交互、控制执行并保存状态和结果。页面刷新、关闭和服务重启后，已有任务及依据仍可查询。

## Solution

提供登录后使用的本机 PoC。创建入口仅提供黑盒 Web App Pentest，前端只配置开源版 Strix 原生支持的 Target、Authentication / Instructions、Scan Mode 和 Resource Budget。支持 Web Application、IP Address、API Specification 及多个目标输入；不加入 White-box、Git Repository、Local Codebase、SAST 或源码修复能力。

保留现有视觉风格及主要页面结构。Home 增加对话输入，AI Copilot 共用全屏与侧边栏两种形态，聊天中的测试需求生成待确认配置卡片。Pentests 汇总创建、执行详情、发现与产物。运行服务连接真实 Strix，保存状态与事件，同一时间执行一个测试任务，并保留任务内部的多 Agent 协作。

本期不建设整改、补丁安装及资产责任管理。报告格式和审批实现方式继续待定；原生结果和产物需可查看、下载。

## User Stories

1. 作为平台用户，我希望登录后使用功能，以便在已登录会话中操作测试及查看记录。
2. 作为平台用户，我希望 Home 保留现有展示项目并展示真实数据，以便了解实际任务和结果。
3. 作为平台用户，我希望从 Home 输入消息并进入全屏聊天，以便直接描述测试需求。
4. 作为平台用户，我希望其他页面打开 Copilot 时默认显示侧边栏，以便保留当前页面上下文。
5. 作为平台用户，我希望在全屏和侧边栏之间切换时保留消息、附件和任务关联，以便持续交互。
6. 作为平台用户，我希望全屏聊天保留左侧导航，以便随时访问其他功能。
7. 作为平台用户，我希望退出全屏后恢复原页面及其状态，以便继续原有操作。
8. 作为平台用户，我希望普通问答得到正常回复，以便在没有创建测试时也能使用 Copilot。
9. 作为平台用户，我希望聊天中的测试要求生成可检查的配置卡片，以便补齐资料并明确确认启动。
10. 作为平台用户，我希望聊天界面的“开始渗透测试”跳转 Pentests，以便通过统一入口创建测试。
11. 作为平台用户，我希望导航使用 Pentests 且移除 Sessions 独立入口，以便按已确认的信息结构使用产品。
12. 作为平台用户，我希望原 Workspace 更名为“现有风险”且内容保持不变，以便保留现有页面用途。
13. 作为平台用户，我希望创建黑盒 Web App Pentest，以便验证运行中的 Web 应用和 API。
14. 作为平台用户，我希望选择 Web Application、IP Address 或 API Specification 目标类型，以便匹配实际测试对象。
15. 作为平台用户，我希望添加多个目标或导入目标列表，以便一次配置多个授权目标。
16. 作为平台用户，我希望填写 Custom Instructions 或上传 Instruction File，以便提供认证信息和测试要求。
17. 作为平台用户，我希望选择 Quick、Standard 或 Deep 扫描模式，以便控制测试深度。
18. 作为平台用户，我希望设置可选的 LLM 费用上限和单 Agent 回合上限，以便控制资源消耗。
19. 作为平台用户，我希望在启动前查看目标类型、指令配置状态、扫描模式和资源限制，以便明确确认测试。
20. 作为平台用户，我希望确认汇总配置之后才启动测试，以便避免仅聊天或浏览页面就产生执行。
21. 作为平台用户，我希望保存可复用测试配置，以便通过 Workflows 再次创建同类任务。
22. 作为平台用户，我希望实际测试在后台执行，以便关闭或刷新网页后任务继续运行。
23. 作为平台用户，我希望查看 Agent、工具调用及状态变化，以便掌握真实执行过程。
24. 作为平台用户，我希望查看主 Agent 与子 Agent 的父子关系和分工，以便理解任务组织情况。
25. 作为平台用户，我希望向主 Agent 或选定子 Agent 插话，以便补充信息和调整指示。
26. 作为平台用户，我希望区分消息已受理和 Agent 已响应，以便准确理解交互状态。
27. 作为平台用户，我希望请求中止指定 Agent 及其子树，以便停止对应工作。
28. 作为平台用户，我希望中止主 Agent 子树并查看实际结束状态，以便控制整项测试。
29. 作为平台用户，我希望暂停并恢复执行，以便控制模型调用及费用额度。
30. 作为平台用户，我希望看到暂停、中止的过渡状态，以便知道当前操作是否已经停止。
31. 作为平台用户，我希望查看真实漏洞发现、复现依据和证据，以便判断测试结论。
32. 作为平台用户，我希望查看和下载 Strix 生成的报告及文件，以便保留测试成果。
33. 作为平台用户，我希望查询历史任务及中断状态，以便在服务重启后继续处理。
34. 作为平台用户，我希望满足条件时恢复原任务，以便利用已保存的执行状态。
35. 作为平台用户，我希望复制配置创建新的测试记录，以便保留旧结果并重新测试。
36. 作为平台用户，我希望目标列表、API 规范和指令文件进入独立运行输入，以便保护原始上传内容。
37. 作为平台用户，我希望查看 Strix 现有 Skills、Tools 的详情、可用情况和实际使用情况，以便了解已接入能力。
38. 作为平台用户，我希望在一个入口配置接口地址、API Key、模型名称并测试连接，以便供所有任务共用。
39. 作为平台用户，我希望敏感身份资料不进入普通日志、报告或可复用配置正文，以便避免交付材料暴露凭据。
40. 作为平台用户，我希望协同通道入口保持空状态，以便维持已确认导航且不误认为已完成渠道接入。

## Implementation Decisions

### 已确认的职责与约束

- 前端负责输入、确认、事件与结果展示及控制请求；运行服务负责独立于网页连接执行任务、保存数据并连接 Strix。
- 通过单独适配模块连接固定版本 Strix，复用原生 Agent、Skills、Tools 和执行能力，不增加自研测试工具或修改测试内核作为默认方案。
- 当前研究涉及不同 Strix 提交。实施时固定实际采用提交及依赖，目录数量、方法签名和恢复行为针对该版本核查，不能混合不同版本的统计作为验收依据。
- 本机同一时间运行一个测试任务。主 Agent 与子 Agent 的内部协作保留；另一任务占用执行资源时，启动操作需要明确反馈，不能静默并行运行。
- 页面模型配置只有一套：接口地址、API Key、模型名称、连接测试；不增加按任务或子 Agent 分配模型的界面。
- 平台登录为必需功能；具体登录技术尚未选择。被测应用的认证信息通过 Custom Instructions 或 Instruction File 传递，不增加独立认证模式选择器。
- Home 保留现有展示项；Tasks 更名为 Pentests；移除 Sessions 侧栏入口；Workspace 更名为“现有风险”且内容不变。
- 全屏聊天占据主内容区域并保留左侧导航，其他页面默认侧边栏。两种形态共用同一会话，切换不重复发送首条消息或创建任务。
- 聊天打开后右上角入口改为“开始渗透测试”，点击跳转 Pentests。普通聊天不自动启动测试；表单和聊天配置卡片共用任务确认规则。
- 普通聊天通过同一模型配置提供；Strix 测试与普通问答的生命周期分开处理。
- Workflows 保存可复用测试配置，不强制定义固定执行步骤。首批 Skills/Tools 使用原生内容，列表存在、环境可用和实际使用分别表达。

### 数据与操作约定

- 测试草稿保存目标类型、目标列表、目标来源、Instruction 来源、扫描模式和资源限制。明确确认启动后形成一次执行记录。
- 执行记录保存实际输入版本、有效配置、模型标识、时间、状态及 Strix 运行标识，不把密钥作为普通配置快照保存。
- 会话保存消息、附件和任务关联；消息额外记录接收 Agent、发送时间、受理及响应情况。
- Agent 记录身份、父子关系、任务描述和原生状态。工具调用记录工具及参数的适当展示、结果、时间和产物引用，不展示模型隐藏推理。
- 发现保存原生严重程度、描述、影响、复现及证据等字段；缺少证据时标明情况，不宣称平台已经独立验证。
- 产物关联执行记录，保存类型、来源及实际文件引用，支持已登录用户查看和下载。
- 流程需要支持读取和保存草稿、确认启动、读取任务和事件、发送消息、中止 Agent/任务、预算暂停恢复、恢复执行、再次测试、读取发现及产物、保存配置和测试模型连接。
- 对外请求的具体 URL、传输协议和数据库选择属于下一步技术设计。本规格不将尚未讨论的实现写为用户已选定方案。
- 状态与事件通过 Strix 适配模块汇入后台并保存。页面连接恢复后读取当前快照及历史事件，不仅依赖当前浏览器内存。
- 状态由执行端结果决定。控制请求受理后可显示过渡状态，只有得到实际状态反馈后才显示暂停或结束。

### 原生控制语义

- 发送消息连接 agent.send_message 对应行为，默认主 Agent，允许指定子 Agent。
- agent.stop 对应行为针对 running、waiting、budget_paused 状态中的指定 Agent 及其子树；停止主 Agent 子树用于任务中止。
- 停止请求不等于已经即时终止所有外部工具进程；任务最终状态和仍在执行的操作需按实际反馈显示。
- pause_budget、resume_budget 为协调器能力，需由适配层连接，不能按已存在同名 TUI 命令处理。
- 暂停一般在下一次模型调用前生效，当前调用及工具操作可能继续完成并计费。
- 恢复预算调整的是模型费用上限；费用耗尽时需要提高有效额度，不能把恢复描述为自动顺延时间。
- event_sink、status_sink 为接入方向，具体签名及回调执行方式针对选定提交验证。

### 持久化、恢复及输入保护

- 保存任务、配置、会话、消息、Agent 活动、工具事件、发现、原生恢复材料及产物引用。
- 刷新或关闭网页不终止后台测试；服务重启保留记录，检查实际执行状态并识别中断，不自动重新测试。
- 恢复执行依据原生状态及有效环境，仅在满足条件时提供。状态记录存在不等于任意断点均可恢复。
- 再次测试复制配置并经确认创建独立记录，保留原结果；不得把它显示为原任务恢复。
- 黑盒目标、目标列表、API Specification、Custom Instructions 和 Instruction File 按独立运行输入保存；不自动提交、推送或部署。
- 本地地址按执行环境检查可达性；容器内 localhost 不视作宿主机地址。
- 敏感凭据单独存储并用于本次执行，普通日志、对话展示、可复用配置正文及报告不输出凭据。具体密钥存储机制由技术设计明确。

## Testing Decisions

### 已确认的测试边界

主要在“登录后的用户通过页面或任务接口完成操作并观察结果”这一公开边界验收。通过创建、读取和控制接口以及页面观察行为，不以数据库内部结构或私有函数调用次数作为业务验收标准。

1. 页面与公开任务接口的行为测试：覆盖聊天双形态、创建确认、持久化读取、消息与控制、发现和产物。可以使用受控执行替身产生确定事件，但替身通过不代表 Strix 已完成集成。
2. 同一用户操作路径的真实 Strix 集成测试：固定目标、模型配置、版本和输入，验证执行标识、实际工具事件、状态及产物。恢复和中止依据实际运行结果检查，不只检查按钮或 HTTP 成功响应。

主要边界能覆盖用户操作到结果展示的路径；执行容器内部和工具子进程的取消行为还需真实运行确认。具体测试框架和现有测试复用方式待实施前检查。

### 当前测试基础

已检查的项目脚本包含类型检查、ESLint 与构建；项目清单未声明专用测试脚本或测试框架。此前前端检查记录不视为本次真实 Strix 集成证据。采用何种测试工具需要在实施任务中明确，不先写成已具备条件。

### 验收场景

- 未登录访问受保护操作时要求登录；登录后可创建和读取自身可访问的任务。
- Home 首条消息进入全屏且只发送一次；侧边栏与全屏切换保留消息、附件及原页面状态。
- 聊天中的普通消息不产生测试；生成任务草稿、补齐字段、确认之后才启动。
- 导航名称与职责符合要求，现有风险内容不被替换，协同通道显示空状态。
- Web App Pentest 支持 Web Application、IP Address、API Specification 和多个目标；目标列表、空行及注释处理符合原生规则。
- 表单与聊天卡片相同输入产生一致的有效测试配置；缺少必要输入不得启动。
- 同时启动第二项任务时不出现两个并行测试；用户收到明确状态反馈。
- Agent 和工具列表来自真实配置及执行事件，空任务不出现固定示例计数。
- 插话展示接收对象及实际受理情况；中止子 Agent 不被误报为整项测试已结束。
- 暂停期间明确当前操作是否仍在完成；恢复调整预算后按原生结果继续，额度不足不显示持续正常运行。
- 刷新、关闭网页后可重新读取执行；服务重启后保留记录，已中断任务不被显示为仍在正常执行。
- 可恢复任务使用原保存状态；不满足条件时说明原因；再次测试形成新执行记录且原结果保持。
- API Specification、目标列表和 Instruction File 进入独立运行输入，原始上传内容保持不变，无自动提交、推送及部署。
- 查看和下载实际发现与产物，文件缺失和未生成报告均有明确反馈。
- 模型密钥及 Custom Instructions 敏感内容不出现在普通日志、配置正文及下载报告中。

代码质量检查包括类型检查、静态检查和生产构建；这些检查与真实执行验收分别记录。未运行的场景不得标记通过。

## Out of Scope

- 资产及责任管理、补丁安装、整改协作、供应商协作、自动部署和业务检查关闭流程。
- 逐工具审批、审批挂起与回执执行机制；实现方式待定。
- Caido iframe、跳转及人工流量工作台入口；Strix 运行所需代理依赖仍按实际需要提供。
- 多执行节点、并行任务调度、多模型目录及子 Agent 模型分配。
- GitHub 应用安装、仓库自动同步、White-box、Git Repository、Local Codebase、SAST、源码修复、商业计费、周期运行、邮件通知和外部协同渠道。
- 新增自研测试工具或技能、在线工具市场及技能编辑器。
- 固定检出率或运行费用承诺、独立复核器、截图中额外的 Network/Terminal 等界面。
- 自定义报告格式、Word/PDF模板及额外导出能力，等待单独讨论。

## Further Notes

- 商业版流程仅用于界面参考；本期前端能力以开源版 Strix 原生黑盒参数为准。
- 原需求说明书覆盖的长期治理能力不自动计入此规格。审批和报告格式之外，登录机制、会话历史入口及具体接口协议仍需技术设计决定。
- 测试边界已由用户确认；拆分包含页面、接口、执行及验收的完整任务，按任务依赖组织实施；单回合文件数量限制仅适用于 Antigravity。
- 任务跟踪使用用户确认的 Onsen626/PennyHub GitHub Issues，本规格按 ready-for-agent 状态发布。实施任务须依据已批准的拆分及依赖单独建立，当前规格不代表这些任务已创建。
- 本文描述待实施与待验收行为，不代表任何真实测试、恢复或控制功能已经完成。
